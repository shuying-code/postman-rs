# postman-rs (pmrs) User Manual

> Applies to v0.1.0+ (GUI `pmrs-gui` and CLI `pmrs`).
> This manual is for end users: install, UI, request building, collections & environments, import/export, runner, code generation, protocol tools, and FAQ.
> Quick overview: [README](../README.en.md). Changelog: [CHANGELOG](../CHANGELOG.md).

---

## 1. Overview

postman-rs is a **local, account-free, pay-free, membership-free** Postman-style API client written in **Rust**. It reproduces Postman's most-used **local** capabilities, is **Postman Collection v2.1** compatible, and runs as a cross-platform **single, install-free binary**.

| Form | Program | Use case |
|---|---|---|
| GUI | `pmrs-gui-windows-x64.exe` | Day-to-day API debugging, visual editing |
| CLI | `pmrs.exe` | Scripting, CI, batch runs |

> No cloud connection, no login, no subscription, no telemetry; **all local features are unconditionally available**.

---

## 2. Install & Launch

### Windows (install-free)
1. Download `pmrs-gui-windows-x64.exe` (GUI) and/or `pmrs-windows-x64.exe` (CLI).
2. **Double-click** the GUI exe to run — **no installation** needed (green single file).
3. If SmartScreen blocks it: "More info → Run anyway".

### macOS
Use `pmrs-gui-macos-universal` (arm64 + x86_64). If Gatekeeper blocks it:
`xattr -d com.apple.quarantine ./pmrs-gui-macos-universal`, or right-click → Open.

### Linux
`chmod +x pmrs-gui-linux-x64 && ./pmrs-gui-linux-x64`.

### Container (CLI only)
```bash
docker run --rm ghcr.io/shuying-code/postman-rs:latest send "https://httpbin.org/get" -m GET
```

## 3. UI Overview

Layout: **left navigation + right workspace**.

- **Top bar**: brand gradient, global search, environment selector, theme selector, refresh.
- **Left nav (segmented)**: `Collections / Environments / Globals / History / Tools / Console`.
- **Right main area**: multi-tab request builder and response panel.

| Page | Purpose |
|---|---|
| Collections | Collection / folder / request tree; click a request to load it |
| Environments | Add/edit environment variables, switch the active environment |
| Globals | Maintain global variables |
| History | View request history |
| Tools | Import, collection runner, code generation, cookie manager, WebSocket workbench |
| Console | Segmented request/response and script-test logs (clear / copy all) |

## 4. Quick Start: Send Your First Request

1. Click "＋ New Tab" (or `Ctrl+N`); an empty left panel on first run is normal.
2. Choose `GET`, enter `https://httpbin.org/get`.
3. Click "Send" (or `Ctrl+Enter`).
4. Inspect Body / Headers / Cookies / Tests / Timing below.

> Import samples to explore: `pmrs import examples/demo_collection.json --format postman`, then refresh the collections panel.

---

## 5. Request Builder

Each tab has these sub-tabs:

- **Params**: query key/value table synchronized with the URL query.
- **Auth**: `None / Bearer Token / Basic Auth / API Key` (header or query).
- **Headers**: row-based key/value editing (key ~30%, value the rest).
- **Body**: `none / form-data / x-www-form-urlencoded / raw / binary / GraphQL`.
  - `raw` supports `Text / JSON / XML / HTML / JavaScript` with one-click format;
  - form types support per-row enable/key/value/type (text or file);
  - `GraphQL` has dedicated Query and Variables editors.
- **Tests**: declarative assertions (see §10).
- **Scripts**: pre-request / test scripts (lightweight `pm.*`).
- **Settings**: request-level settings (e.g., timeout).
- **Desc**: Markdown description saved to `item.description`, preserved on v2.1 export.

Sending runs on a background thread (UI stays responsive); `{{variables}}` and the active environment are resolved.

## 6. Tab Management

- **New**: "＋ New Tab" or `Ctrl+N`, name it and pick a method.
- **Rename**: **click the active tab title** or **double-click any tab name** for inline edit; `Enter` saves, `Esc` cancels; clearing the name keeps the old name.
- **Close**: `×` on the tab or `Ctrl+W` (confirmation).
- **Switch**: click a tab title.

---

## 7. Variables & Environments

- Syntax `{{name}}`, resolved recursively before sending.
- Scope priority (high → low): `CLI vars > iteration data > environment > collection > globals`.
- Dynamic variables: `{{$randomInt}}`, `{{$randomUUID}}`, `{{$guid}}`, `{{$timestamp}}`, `{{$isoTimestamp}}`, `{{$randomEmail}}`, `{{$randomCity}}`, plus `$randomLorem*` / `$randomImageUrl` / `$randomAvatar` etc. (30+).
- Environments: the "Environments" page edits variables; the top bar switches the active environment.

---

## 8. Collections & Folders

- Collection / folder / request tree; collection variables supported.
- **Save current request**: click "Save"; blank collection name = current collection, blank request name = tab title.
- **Inheritance**: folder/collection-level auth, variables and pre-request/test scripts are inherited on send; global variables apply in GUI sends.

## 9. Import & Export

**Import (Tools → Import)**: `Postman v2.1/v2.0/v1`, `OpenAPI 3 / Swagger 2 (JSON)`, `cURL`, `HAR`; collections with the same name are merged.

```bash
pmrs import examples/openapi.json --format openapi
pmrs import "curl 'https://api.test/x' -X POST -d '{\"a\":1}'" --format curl
pmrs import har.json --format har
```

**Export**: collection → Postman v2.1 JSON (blank path = `~/.postman-rs/exports/`). The URL bar **cURL** button menu offers: Copy as cURL / Export as cURL script / Import from cURL (paste).

---

## 10. Assertions (Tests)

Declarative: `status / json_path / json_path_exists / body_contains / body_equals / header / max_time_ms / response_time / regex`; plus common `pm.test(...status(200))` / `to.have.header(...)` parsing. The "Tests" panel shows each result.

---

## 11. Collection Runner

Tools → Collection Runner, or:

```bash
pmrs run examples/demo_collection.json -e examples/demo_environment.json -i 3
pmrs run collection.json -d data.csv --delay 200 --bail
```

Multi-iteration, CSV/JSON data-driven, delay, assertion stats, fail-fast (`--bail`), CI exit code, report (`--report`).

---

## 12. Code Generation

Tools → Code Generation, or:

```bash
pmrs codegen --collection examples/demo_collection.json --item "Get Hello" --lang rust
pmrs codegen --url https://api.test/x --method POST --lang curl
```

Languages: `curl / http / rust(reqwest) / python(requests) / js(fetch) / go(net/http) / nodejs(axios) / java(okhttp) / csharp / php / ruby / powershell / swift`.

## 16. Network & Certificates

| Variable | Purpose |
|---|---|
| `PMRS_PROXY` | HTTP/SOCKS proxy |
| `PMRS_CA_BUNDLE` | Custom CA bundle (PEM) |
| `PMRS_CLIENT_CERT` / `PMRS_CLIENT_KEY` | Client cert / key (mTLS) |
| `PMRS_INSECURE=1` | Skip TLS verification |
| `PMRS_CONNECT_TIMEOUT` | Connect timeout (s) |
| `PMRS_MAX_REDIRECTS` | Max redirects (default 10) |

Persistent cookies: `~/.postman-rs/cookies.json`.

## 17. Workspace & Files

Default `~/.postman-rs` (override with `PMRS_HOME`): `collections/*.json`, `environments/*.json`, `exports/`, `history.jsonl`, `cookies.json`, `gui_theme.txt`. Plain files, git-friendly, no database, no cloud.

## 19. FAQ

**Where are the built files?** GUI `dist/pmrs-gui-windows-x64.exe`; CLI `dist/pmrs-windows-x64.exe`.
**Windows says "cannot install"?** It's a green single file — just double-click the exe.
**How to change theme?** Top bar "Theme", or `PMRS_THEME=0..7`.
**How to get the macOS build?** Build on a real Mac via `scripts/build-macos.sh`, or use the repo CI.
**Account or payment needed?** No. No login, subscription or membership limits.
