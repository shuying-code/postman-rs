# 补充二：登录 / 收费 / 会员限制分析与去除方案

> 目标：明确 Postman 12.34.4 中「必须登录 / 必须付费 / 必须会员」的边界，并给出**合法、仅用于自建替代实现**的去除思路。配套 Rust 复刻项目默认**无条件全功能**（不含任何账号、订阅、配额逻辑）。

---

## 1. 结论先行

Postman 桌面端的限制大体分两类：

1. **云端能力**（真正需要登录 + 订阅）：同步、团队、云端 Mock/Monitor、Vault、API Governance、在线文档、CLI 云端上报、AI 等。这些依赖 `identity.getpostman.com` / `auth.postman.com` / `app.getpostman.com` 后端，客户端无法本地「解锁」其真实数据，因为它们本质上不是本地功能。
2. **本地能力**（本不需登录）：HTTP 发送、集合/环境/变量、历史、Runner、代码生成、导入导出、部分多协议工作台、本地 Mock。Postman 已内置 **Scratch Pad 离线模式** 提供这些能力；甚至存在 `SKIP_SIGNIN` 环境开关。

因此「去除登录/收费/会员限制」最干净的做法**不是破解云端**，而是：**构建只含本地能力、且不接入任何计费/鉴权后端的实现**。这就是本任务 Rust 项目的定位。

---

## 2. 登录相关证据

### 2.1 启动链中的跳过开关（关键）
`main.js` 启动逻辑：
```js
Promise.resolve().then(async () => {
  if ("true" !== process.env.SKIP_SIGNIN)
    return (await import("./services/AuthHandler.js")).default.init();
}).then(() => J.initialize({eventBus: u}))
```
- 当环境变量 `SKIP_SIGNIN=true` 时，**不会初始化 AuthHandler**（登录处理），直接进入主窗口初始化。
- 这是 Postman 官方保留的 CI/测试开关，用于 E2E 与自动化场景。

### 2.2 离线模式（Scratch Pad）
`js/desktop-offline.js` 中的错误/降级页：
- `isSignedOutUser`（未登录用户）分支渲染 `eh` 组件，提供按钮 **`Switch to Scratch Pad`**。
- 点击后 `navigateToScratchpad`（IPC `NAVIGATE_TO_SCRATCHPAD`），加载 `html/scratchpad.html`。
- Scratch Pad 是**完整本地工作台**（集合/环境/历史/请求/runner/代码生成/转换器），不依赖账号。

### 2.3 登录动作与身份服务
- `AUTH_ACTIONS = { SIGN_UP, LOGIN, SWITCH_USER, LOGOUT, SKIP }`，其中 `SKIP` 对应「跳过登录」。
- `AuthHandler` 通过 `identity.getpostman.com`/`auth.postman.com` 做 OAuth 令牌交换（`startPpcLogin` → `token exchange succeeded`）。
- `services_AppRefreshTokenManager` 负责刷新 token；每用户分区 `associateUserAndPartition`。

### 2.4 结论
- **不登录也能用**：走 Scratch Pad 即可；或在启动时设 `SKIP_SIGNIN=true`。
- 本地功能不因未登录被阉割；被限制的是「需要后端账号态」的功能。

## 3. 收费 / 会员相关证据

### 3.1 构建期计费配置（config.json）
| 配置 | 值 | 含义 |
|---|---|---|
| `__WP_PRELOGIN_PURCHASE_URL__` | `https://www.postman.com` | 登录前购买页 |
| `__WP_ALLOWED_PAYMENT_HOSTS__` | `js.stripe.com`、`api.stripe.com`、`hooks.stripe.com`、`pay.google.com`、`checkout.stripe.com`、`www.google.com`、`recaptcha.google.com`、`www.postman.com` | 支付/风控白名单 |
| `__WP_TRIAL_DURATION__` | `2592000000`（ms）= **30 天** | 试用期 |
| `__WP_IDENTITY_URL__` / `__WP_GLOBAL_IDENTITY_URL__` | 身份服务 | 账号/订阅态来源 |

`main.js` 初始化了 `initPaymentView`（`services/paymentView.js`），即内嵌支付视图；付款页只被允许在上述域名内加载。

### 3.2 订阅/套餐判定
- 用户套餐（Free/Basic/Pro/Team/Enterprise）来自云端身份接口返回的用户/团队对象；客户端本地不做可靠的「功能解锁」计算，而是依据后端返回的 entitlements 决定 UI 展示。
- `usageLimit`、`quota` 等字符串出现在 `scratchpad.js`、`RequesterModalContainer.js`、`ECItemWorkbench.js`、`DocumentationContextBarView.js` 等，主要对应**云端资源**（Mock 调用次数、Monitor 运行、AI 额度、文档发布等）的用量与上限提示。

### 3.3 免费 / 付费功能边界（归纳）

| 功能 | 免费（未登录也可，在 Scratch Pad） | 需订阅/会员 |
|---|---|---|
| 本地 HTTP 发送、集合、环境、变量、历史 | ✅ | — |
| Collection Runner、代码生成、导入导出 | ✅ | — |
| 本地 Mock Server | ✅ | — |
| 云端同步 / 团队库 / 多人协作 | ❌ | ✅ |
| 云端 Mock（托管 URL、调用配额） | ❌ | ✅ |
| 云端 Monitor（定时运行、告警） | ❌ | ✅ |
| Vault（团队密钥） | ❌ | ✅ |
| API Governance / 安全治理 | ❌ | ✅（多为 Enterprise） |
| 在线 API 文档发布 | ❌ | ✅ |
| AI 功能（Postman AI） | 受限 | ✅ |
| 更高配额（Mock 调用、Monitor、上传大小等） | 低配额 | ✅ |

> 说明：不同版本与套餐的配额细节会随云端策略变化（属动态数据，不在本地包内固定），此处为**功能边界**层面的归纳，而非逐项数值承诺。

## 4. 去除限制的可行方案（面向自建替代）

### 4.1 方案 A（推荐）：只实现本地能力，永不计费
- 不接入 `identity/ auth/ app.getpostman.com`、Stripe、任何 license 校验。
- 所有功能对任何人无条件开放；无账号、无试用期、无配额。
- 这就是本任务 Rust 项目的设计基线（见 `04_补充三`）。
- 优点：合法、可长期维护、跨平台、无云端单点依赖。

### 4.2 方案 B：原程序离线化（仅研究，不建议分发）
- 启动时设置环境变量 `SKIP_SIGNIN=true` 绕过登录初始化，进入本地/Scratch Pad 流程。
- 在无网络或阻断身份域名时，客户端会降级到 Scratch Pad 错误页，可点「Switch to Scratch Pad」。
- 注意：这仅影响「入口」，**不能让云端功能变成本地可用**；也无法凭空获得云端数据。对 asar 打补丁（如改 `config.json` 的购买页/支付域）属于修改软件，**可能违反许可与法律**，本报告不提供具体补丁代码，不建议用于分发。

### 4.3 方案 C：混合（本地为主）
- 用本地实现覆盖 90% 日常需求（发送/集合/环境/历史/runner/导入导出/代码生成/本地 Mock/WebSocket）。
- 需要团队协作时再选任意第三方后端（git 仓库、对象存储、自建 API），不依赖 Postman 云。

## 5. Rust 复刻中的「无条件」原则（落地约定）

复刻项目 `postman-rs` 遵守：

1. **零账号**：无登录、无 token、无 OAuth、无遥测上报。
2. **零计费**：无 paywall、无试用、无订阅判断、无 Stripe。
3. **零云配额**：本地无请求次数/集合数/环境数上限；仅受本机资源约束。
4. **全功能默认开启**：所有已实现命令直接可用，无需「解锁」。
5. **数据本地化**：集合/环境/历史/导出均保存在用户指定目录，纯文件，可版本控制。
6. **可选离线**：运行时不需要任何网络，除了自身要访问的目标 API。

这些约定写入项目 `README.md` 与 `docs/`，作为验收标准的一部分（见 `04_补充三` 的验收清单）。
