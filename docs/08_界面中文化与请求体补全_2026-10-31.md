# 界面中文化 + 请求体补全（本轮修改记录）

> 对象：`F:\codex工作区\postman-rs`　日期：2026-10-31

## 1. 需求
1. 界面尽可能用中文；
2. UI 中输入框尺寸尽量与 Postman 一致；
3. 检查并补全「请求体」缺失的功能。

## 2. 请求体：原来缺什么
旧版 GUI 的 Body 类型下拉只有 `json / text / none` 三种，且内部只构造 `mode=raw`。
后端引擎明明支持 `raw / urlencoded / formdata / file / graphql`，但图形界面没有暴露对应编辑器，
导致“form-data、x-www-form-urlencoded、binary 文件、GraphQL 查询”在 GUI 里做不出来 —— 这就是缺失点。

## 3. 本轮已补全（对齐 Postman 的 6 种 Body 类型）
| 类型（中文标签） | 内部 mode | 编辑器能力 |
|---|---|---|
| 无 | none | 无请求体 |
| form-data 表单 | formdata | 逐行：启用 / 键 / 值 / 类型（文本·文件）；文件行填本地路径 |
| x-www-form-urlencoded 表单 | urlencoded | 逐行：启用 / 键 / 值 |
| raw 原始 | raw | 子语言 `Text/JSON/XML/HTML/JavaScript` + JSON 一键格式化 |
| binary 二进制 | file | 选择本地文件作为原始请求体 |
| GraphQL 查询 | graphql | 独立 Query 编辑框 + Variables(JSON) 编辑框 |

导入请求时也会按 `body.mode` 反向还原到对应编辑器；保存/代码生成走同一 `build_request()`，
因此发送、保存、导出、生成代码的请求体与实际一致。

## 4. 界面中文化
- 请求体类型、raw 语言、导入格式、授权类型（无 / Bearer 令牌 / 基本认证 / API 密钥）等均改为中文；
- 输入框占位提示 `key/value/Header/Token` → `键/值/请求头名/令牌`；
- HTTP 方法、语言名（curl/python…）、Cookies 等专有名词保留原样。

## 5. 输入框尺寸
- 参数 / 请求头 / urlencoded / form-data 的键值行改为**按可用宽度自适应**：键列约 30%，值列占其余，行高与行间距对齐 Postman；
- 环境变量编辑器同样按比例自适应列宽。
