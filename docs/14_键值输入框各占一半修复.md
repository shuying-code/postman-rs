# 键/值输入框「各占一半」修复记录

> 针对用户反馈：参数页「键 / 值」输入框太小（红框），要求「各占一半」，并检查其他同类位置一并修改。

## 1. 根因

`ui_params` / `ui_kv_editor` / 路径变量 / 授权扩展等页面此前使用 `egui::Grid` +
`desired_width(key_w/val_w)`，其中 `key_w/val_w` 由 `ui.available_width()` 计算。但这些
控件位于 `ScrollArea::vertical().show(ui, |ui| { ui.set_width(content_w); ... })` 内部，
`ScrollArea` 内部的 `available_width()` 会被放大，导致网格宽度塌缩，「键 / 值」被压成极窄的框
（即截图中的红框）。

## 2. 修复方式（统一为「各占一半」水平布局）

每个键值行改为 `ui.horizontal(...)`：

- 计算 `rem = available_width - 预留(删除按钮/类型下拉)`；
- `half = (rem - gap) / 2`；
- 「键」「值」各 `add_sized([half, ROW_H], TextEdit)`，即各占剩余宽度的一半并填满卡片；
- 删除「×」/类型下拉放在两半之后，避免抢占宽度。

覆盖范围：

- 参数（查询参数）`ui_params`
- 路径变量 `pathvars`
- 请求体 `x-www-form-urlencoded` / `form-data`（`ui_kv_editor`，含「启用」勾选与「类型」下拉）
- 授权扩展 `OAuth1 / AWS SigV4 / JWT / Digest`（`auth_extra`）
- （请求头 `ui_headers`、环境/全局编辑器此前已用 `ui.columns(2)` 等分，保持正常）
